# Minecraft API coverage

This is a source-based coverage matrix for the current target checkout at host **0.105.0**,
SDK/macros **0.103.0**, private CLI **0.1.35**, ABI **1.95.0**, Minecraft **1.21.1**, and NeoForge
**21.1.265**. It records the public surface that exists in this tree, its path
from a Minecraft hook to Rust/WASM, and the limits that remain. It is not a
roadmap or a claim of complete Minecraft mod compatibility. The matrix tracks
the current working tree. The verification record below covers this target.

For guest-call rows, the Java host binds named WebAssembly imports through
[`ModuleImports`](../sjml-core/src/main/java/dev/somuch/sjml/core/runtime/ModuleImports.java),
which validates import names and signatures and exposes only bindings supplied
by the relevant host adapter. [`AbiMemory`](../sjml-core/src/main/java/dev/somuch/sjml/core/abi/AbiMemory.java)
and [`AbiCodec`](../sjml-core/src/main/java/dev/somuch/sjml/core/abi/AbiCodec.java)
bound and encode the byte boundary; domain-specific schemas/codecs are cited
where present. Rust `extern` imports and public wrappers are in the cited SDK
files. Registration callbacks and event-export callbacks use their own
documented ABI paths rather than a host import for every operation.

## ABI 1.89.0 addition

Registered SJML mobs can use bounded `AvoidEntityType` and `TargetEntityType`
goals against one exact registered living entity type. The host keeps vanilla
pathfinding and targeting conditions, adds a type predicate, and skips unknown
registry IDs with a warning. Vanilla selectors only consider living entities,
so non-living registered types never match. The static import
`register_entity_ai_goal_v3` is available only during `mod_register` under
`content.register`; goal count, range, speed, and canonical ID limits remain
enforced. [`EntityAiGameTests`](../src/main/java/dev/somuch/sjml/neoforge/registry/EntityAiGameTests.java)
checks that the declared target matches a cow and rejects a closer pig.

## ABI 1.88.0 addition

Logical-server modules can synchronously veto a living entity's bounded item
drop list with `entity.drops_attempt`; the entity still dies. The detached
snapshot contains entity identity, dimension, recent-hit state, and up to 32
item IDs/count/durability snapshots. It requires both event capabilities and
cannot run asynchronously.

## ABI 1.87.0 addition

Logical-server modules can synchronously veto mounts and dismounts with
`entity.mount_attempt` before the riding relationship changes. The detached
snapshot carries the acting entity, an optional mounted entity, dimension, and
mount/dismount direction. It requires `events.subscribe` and `events.cancel`
and cannot run asynchronously. The live path is covered by
[`EntityMountAttemptEventAdapterTest`](../src/test/java/dev/somuch/sjml/neoforge/event/EntityMountAttemptEventAdapterTest.java)
and [`EntityMountAttemptGameTests`](../src/main/java/dev/somuch/sjml/neoforge/gametest/EntityMountAttemptGameTests.java), which veto both a live pig mount and cow dismount.

## Status definitions

- **Fully implemented** means the specifically named contract has a host
  implementation, a Rust-facing API where applicable, and tests for its
  boundary. It does not mean all of Minecraft's related features are covered.
- **Partially implemented** means usable end-to-end operations exist, but a
  significant part of the category requested below is absent or unverified.
- **Not implemented** means no public, vertical SJML API for that capability
  was found in the host/ABI/SDK path. A Minecraft resource file that happens to
  describe related data does not count as a runtime API.
- **Technically unsupported** means the current WASM/security architecture
  deliberately excludes the capability, rather than promising a future API.
- **Requires additional research** means this audit did not establish a safe,
  supported NeoForge extension point or a complete inventory for that area.
